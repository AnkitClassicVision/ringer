# D7 validator amendments

Apply these changes by hand to `checks/check_v91_graph.py`; do not weaken unrelated gates.

1. **Assertion [1], graph counts.** Current expectation: `49` nodes and `127` edges. New expectation: `50` nodes and `134` edges. Justification: D7 adds `n_search_offered_date` plus its one inbound and nine response-pathway edges, and removes the three obsolete outgoing edges from terminal `n_miss_unread` (`127 + 10 - 3 = 134`).

2. **Assertion [2], allowed new node IDs.** Current expectation: the seven D1/D2/D6 IDs only. New expectation: add `n_search_offered_date` to that exact set. Justification: D7's time-preference-only route needs a dedicated webhook whose `from` and `to` both reuse the canonical date prefix carried by `{{slot_1_start}}`; changing shared `n_search` would alter fresh-date searches.

3. **Assertion [4], mutable nodes.** Current expectation: the following v86 nodes remain immutable. New expectation: add `n_clarify`, `n_gate_1`, `n_gate_2`, `n_miss_empty`, `n_miss_thin`, `n_miss_time`, `n_miss_unbookable`, `n_miss_unread`, `n_negotiate`, `n_offer`, `n_offer_2`, `n_offer_near`, `n_recheck`, and `n_which_intent` to `MUTABLE_NODES` (the other six protected-copy carriers are already mutable). Justification: D7a deliberately repairs the shared filler-bearing paragraph in every carrier; `n_negotiate` also loses its second filler, and `n_miss_unread` becomes deterministic terminal referral behavior.

4. **Assertion [5], mutable/pinned edge set.** Current expectation: the three `n_miss_unread` outgoing edges are immutable and the two offer edges equal v86. New expectation: add these five exact IDs to `MUTABLE_EDGES`: `edge-n_miss_unread-n_search-names-any-day-weekday-date-week-or-weekend-including-saturda`, `edge-n_miss_unread-e_declined-gives-up-on-booking`, `edge-n_miss_unread-e_timeout-72-hour-timeout`, `edge-n_offer-n_page_2-wants-later-in-the-day`, `edge-n_offer-n_negotiate-wants-a-different-day-or-time`. Assert the first three are absent; assert the later edge keeps its ID but targets `n_page_3` with label `wants late, latest, last appointment, or end of day on the offered date`; assert the broad edge still targets `n_negotiate` with label `wants a different day and does not give only a time preference`. Justification: terminal nodes have no recovery exits, the mis-targeted edge must reach late search, and the labels must be mutually exclusive.

5. **Assertions [7], [10]-[16], D7 webhook/edge pins.** Current expectation: `AVAIL` contains four webhook nodes and no D7 offer-date route is pinned. New expectation: add `n_search_offered_date` to `AVAIL`, give it expected `time_pref == "none"`, and apply the same body, retry, responseData, and responsePathway/edge-consistency checks as `n_search`; additionally assert its body has `from == "{{slot_1_start}}"` and `to == "{{slot_1_start}}"`. Pin `edge-n_offer-n_search_offered_date-time-preference-only` to source `n_offer`, target `n_search_offered_date`, and label `gives only a time preference on the already offered date, excluding late, latest, last appointment, or end of day`. Justification: this proves a time-only follow-up reuses the established offered date and cannot overlap the late or different-day routes.

6. **Assertion [30], protected paragraph.** Current expectation: each of the 20 carrier prompts contains its byte-identical v86 `ABSOLUTE RULE ON TIMES` paragraph. New expectation: keep the exact same 20-node carrier set and each node-class-specific v86 paragraph, but compute its D7 canonical paragraph with exactly one replacement: old text `say 'One moment while I check the schedule for you.' and run the schedule search.` becomes `Do not send a progress promise. Continue only through an outgoing route that actually performs a schedule search; when no such search can proceed, use the office-referral behavior defined for that node.`; every byte before and after that sentence remains the class-specific canonical text. Apply this to `n_ask`, all five `n_miss_*`, `n_clarify`, four `n_offer*`, `n_which_intent`, `n_gate_1`, `n_gate_2`, `n_negotiate`, `n_recheck`, `n_confirm`, `n_help`, `n_office`, and `n_faq`. Justification: D7a requires both fillers to occur zero times anywhere, including prompts, labels, descriptions, and terminal copy.
