# Mott v94 time-of-day stall: exact mechanism

## Finding

The patient is not waiting on a successful availability result that Bland forgot to print. The offer turn classifies the request into a time-negotiation branch, a silent availability webhook runs, that webhook returns HTTP 409, and the graph routes the failure to `n_miss_unread`. `n_miss_unread` is a generative Default node whose prompt contains two competing recovery policies. It can either emit the promise "One moment while I check the schedule for you" or invoke its call-the-office escalation. Neither policy renders the webhook error or slots, so one outcome is a promise-and-ghost and the other is an office punt.

## Trace with node and edge IDs

1. The patient is on `n_offer` after the Friday 08/14 search produced the 10:30 and 10:45 offers (live transcript `workDiag3/.../diag.txt:5-8`). The `n_offer` prompt explicitly says that "later in the day ... or the latest you have" must take the later-in-the-day path (`pathway-v93-draft.json:2288-2291`).

2. The matching explicit edge is `edge-n_offer-n_page_2-wants-later-in-the-day`, source `n_offer`, target `n_page_2`. Its condition is only "wants later in the day" (`pathway-v93-draft.json:437-450`). The utterance also overlaps the broader `edge-n_offer-n_negotiate-wants-a-different-day-or-time` (`pathway-v93-draft.json:788-800`) and the global `n_negotiate` label, which matches any different time (`pathway-v93-draft.json:2458-2465`). This overlap is a second defect: Bland's LLM edge/global routing can choose the broad negotiation route instead of the specific one. The intended and most specific match is the `n_page_2` edge.

3. Both possible branches issue a silent webhook. `n_page_2` posts `/availability` with `time_pref:"afternoon"`, `after:"{{time_after}}"`, `before:"none"`, and `skipUserResponse:true` (`pathway-v93-draft.json:2659-2672`). `n_negotiate` emits/checks a filler, auto-continues because `userWait:false` and `skipUserResponse:true` (`pathway-v93-draft.json:2458-2465`), then follows `edge-n_negotiate-n_search-preference-collected` to `n_search` (`pathway-v93-draft.json:829-842`), whose request instead has `time_pref:"none"` (`pathway-v93-draft.json:2481-2485`).

4. The live call resolved no date from the current utterance and fell back to pathway variables: `raw_resolve from=None`, `date_source=fallback`, then HTTP 409 (`workDiag3/.../diag.txt:34-39`). That is expected for a time-only utterance in one sense, but unsafe in this contract. The current stored fallback is `preference_from=friday 08/14` (`workDiag3/.../diag.txt:13-14`), while `resolve_relative_date` accepts bare weekdays and numeric dates but not a weekday-prefixed numeric date (`bland_gateway.py:610-625,705-725`). It therefore leaves the noncanonical fallback unresolved; the CLI refuses the request, and the gateway converts a nonzero CLI return into HTTP 409 (`bland_gateway.py:3225-3234`). The earlier incident has the same signature: raw `None`, fallback, HTTP 409 (`workDiag2/.../diag.txt:50-55`). The logs do not include the CLI stderr, so the malformed fallback is a high-confidence inference, not directly proven by these frozen lines.

5. `n_page_2` maps `ok != true` directly to `n_miss_unread` (`pathway-v93-draft.json:2719-2727`). The corresponding `n_search` response pathway does the same through `edge-n_search-n_miss_unread-ok-true` (`pathway-v93-draft.json:1009-1024`). A 409 body has `ok:false` and no successful `result.slots`; the silent webhook has no text renderer. Thus there is no availability response capable of becoming a patient message. What appears next is generated by `n_miss_unread`, not rendered from the gateway response.

6. `n_miss_unread` contains the exact filler sentence in its absolute rule (`pathway-v93-draft.json:2092-2094`). This explains both fillers in the live transcript, including the repeat after "Hello?" while the conversation remains on `n_miss_unread` (`workDiag3/.../diag.txt:1,7-10`). The same prompt also says that after two or more date asks it must stop and send the call-the-office referral (`pathway-v93-draft.json:2092-2094`). Those instructions conflict: the absolute rule commands a schedule-check promise after a nudge, while escalation commands an office punt based on a fuzzy history count. The Default node is model-generated rather than a deterministic response mapping, so history and classifier variation select different instructions. In the earlier longer history, it emitted `n_negotiate`'s "Let me check" followed by the office escalation (`workDiag2/.../diag.txt:11-13`); in the newer history it selected the absolute-rule filler twice.

## Time semantics in the gateway

The gateway does not recognize "last/latest/end of day" itself as a request to select the day's final slot. Those words are interpreted only by the pathway extractor as `day_part=late`. Gateway bands are static: `afternoon` adds `--after 12:00 pm`; `late` adds `--after 03:00 pm` (`bland_gateway.py:310-315`). An explicit `after` clock overrides the band, and literal `none` values for `after`/`before` are removed (`bland_gateway.py:2185-2200`). There is no reverse sort, last-slot selector, or closing-time `before` behavior. Therefore the current direct offer edge is doubly wrong: it sends “latest” to `afternoon`, and even the `late` branch would return the first slots after 3 p.m., not necessarily the last slot of the day.

## Minimal robust fix short of the rebuild

Make one narrow graph patch plus one narrow gateway compatibility patch:

1. Replace the overlapping offer conditions with mutually exclusive intent edges. Route `latest`, `last appointment/time`, and `end of day` from `n_offer` directly to `n_page_3` (or a renamed latest webhook), not `n_page_2`; reserve `n_page_2` for explicit afternoon/midday and make the general different-time edge exclude both bands. This removes nondeterministic ownership.
2. Add `time_pref:"latest"` in that webhook. In the gateway, treat it as a late-day search and select the chronologically last returned slot for the requested date (or last two, presented latest-first). Do not pretend `--after 03:00 pm` means “last.” Preserve `after` precedence for explicit clock requests.
3. Make fallback dates canonical before the CLI call. At minimum, extend `resolve_relative_date` to accept `weekday MM/DD` and `weekday MM/DD/YYYY`, discard the weekday token, validate it against the parsed date when a year is present, and emit `MM/DD/YYYY`. Better within the same small patch: persist the resolved offered date and reuse that canonical date for a time-only follow-up. A time-only message must not require the raw date parser to rediscover a date.
4. Remove the schedule-check promise from `n_miss_unread`. Give it one deterministic bounded failure message, preferably an apology plus office referral, or one actual retry edge with a counter. It must never say it is checking unless an outgoing retry is guaranteed to run and terminate in either an offer or an explicit failure message.

This is smaller than consolidating all four availability nodes, but it fixes routing ownership, last-slot semantics, the malformed fallback responsible for the 409, and the patient-visible terminal behavior. A prompt-only edit would hide the ghost but would not answer the question correctly.
